# Error catalog

Generated by `teslai errors docs`. Do not edit by hand.

## tsl-env-missing

**TSL-ENV-MISSING**: No .env file was found.

- **Likely cause:** teslai has not been initialized in this directory.
- **Fix:** Run `teslai init --domain <your-domain>`.

## tsl-env-incomplete

**TSL-ENV-INCOMPLETE**: A required setting is empty.

- **Likely cause:** The value was never filled in, or still holds a placeholder.
- **Fix:** Edit .env and set the named variable, or re-run `teslai init --force`.

## tsl-secrets-missing

**TSL-SECRETS-MISSING**: The private CA, telemetry certificate or app key is missing.

- **Likely cause:** The secrets directory was deleted or never generated.
- **Fix:** Run `teslai init --force` to regenerate secrets, then re-push the telemetry config.

## tsl-cert-expiring

**TSL-CERT-EXPIRING**: The telemetry server certificate expires within 14 days.

- **Likely cause:** The certificate was issued long ago and has not been rotated.
- **Fix:** Run `teslai init --rotate-server-cert`, then `teslai telemetry push --reason cert-rotate`.

## tsl-ca-mismatch

**TSL-CA-MISMATCH**: The CA in the car's telemetry config does not match the server certificate chain.

- **Likely cause:** The server certificate was reissued under a different CA, or Caddy's public certificate was used instead of the private CA.
- **Fix:** Run `teslai telemetry push --reason ca-fix`.

## tsl-db-unreachable

**TSL-DB-UNREACHABLE**: The database did not accept a connection.

- **Likely cause:** Postgres is not running, or DATABASE_URL is wrong.
- **Fix:** Run `docker compose up -d db` and check DATABASE_URL in .env.

## tsl-mqtt-unreachable

**TSL-MQTT-UNREACHABLE**: The MQTT broker did not accept a connection.

- **Likely cause:** Mosquitto is not running, or MQTT_HOST/MQTT_PORT is wrong.
- **Fix:** Run `docker compose up -d mosquitto` and check MQTT_HOST and MQTT_PORT.

## tsl-tesla-unconfigured

**TSL-TESLA-UNCONFIGURED**: No Tesla developer app is configured yet.

- **Likely cause:** TESLA_CLIENT_ID is empty.
- **Fix:** Register an app at developer.tesla.com, then run `teslai tesla register`.

## tsl-partner-unregistered

**TSL-PARTNER-UNREGISTERED**: Tesla rejected a call because the app is not registered in this region.

- **Likely cause:** The partner-account registration call was never made for TESLA_REGION.
- **Fix:** Run `teslai tesla register`.

## tsl-region-wrong

**TSL-REGION-WRONG**: Tesla returned a region error.

- **Likely cause:** TESLA_REGION does not match the account's region.
- **Fix:** Set TESLA_REGION to na, eu or cn in .env, then run `teslai tesla register`.

## tsl-scope-missing

**TSL-SCOPE-MISSING**: Tesla returned 403 for a field or endpoint.

- **Likely cause:** The owner did not grant a scope the request needs, such as vehicle location.
- **Fix:** Re-authorize with the required scopes via `teslai tesla login`.

## tsl-token-consumed

**TSL-TOKEN-CONSUMED**: The Tesla refresh token was rejected.

- **Likely cause:** Refresh tokens are single-use; another process refreshed first, or the owner revoked access.
- **Fix:** Run `teslai tesla login` to re-authorize.

## tsl-key-unpaired

**TSL-KEY-UNPAIRED**: The car has not accepted teslai's virtual key.

- **Likely cause:** The QR pairing step was skipped or declined in the Tesla app.
- **Fix:** Run `teslai pair` and scan the QR code with the Tesla app.

## tsl-config-null

**TSL-CONFIG-NULL**: The car reports a synced telemetry config of null.

- **Likely cause:** Another app's config is active on the car (fleet-telemetry issue #294).
- **Fix:** Remove the other app's config, then run `teslai telemetry push`.

## tsl-config-unsynced

**TSL-CONFIG-UNSYNCED**: The car has not synced the latest telemetry config.

- **Likely cause:** The car is asleep or offline since the config was pushed.
- **Fix:** Wake the car from the Tesla app, then run `teslai telemetry status`.

## tsl-billing-disabled

**TSL-BILLING-DISABLED**: Tesla disabled the app for exceeding its billing limit.

- **Likely cause:** Monthly Fleet API usage passed the limit set in the developer console.
- **Fix:** Raise the limit at developer.tesla.com, then lower field rates in telemetry.yaml.

## tsl-firmware-too-old

**TSL-FIRMWARE-TOO-OLD**: The car's firmware does not support a subscribed field.

- **Likely cause:** Some fields need newer firmware, for example DetailedChargeState needs 2024.38.
- **Fix:** Update the car's software, or remove the field from telemetry.yaml.

## tsl-vin-rejected

**TSL-VIN-REJECTED**: Telemetry arrived for a VIN that is not in the vehicles table.

- **Likely cause:** A car connected that this deployment does not own, or TESLA_VIN is wrong.
- **Fix:** Check TESLA_VIN in .env. Unknown VINs are dropped by design.

## tsl-import-schema

**TSL-IMPORT-SCHEMA**: A TeslaFi CSV is missing expected columns or changed units.

- **Likely cause:** TeslaFi changed its export format, or the file is not a TeslaFi export.
- **Fix:** Check the named file and columns; re-download the export from TeslaFi.

## tsl-import-tz

**TSL-IMPORT-TZ**: The import timezone is missing or invalid.

- **Likely cause:** TeslaFi timestamps have no offset, so the home timezone must be given.
- **Fix:** Pass --tz with an IANA name, for example --tz America/Chicago.
